# Security

Pastely stores your clipboard history. That makes it sensitive software, so here is exactly what it does and does not do.

## What it does

- History lives in `~/Library/Application Support/Pastely/history.sqlite`, file mode 0600.
- Every payload, preview, thumbnail and recognized text is encrypted with AES-GCM using a 256-bit key kept in your login keychain. Only metadata (timestamp, kind, size, source app, pinned) is stored in clear columns.
- Pasteboard writes marked `org.nspasteboard.ConcealedType`, `TransientType` or `AutoGeneratedType` are never recorded. Password managers use these.
- Copies made while an app on your ignore list is frontmost are never recorded.
- Text recognition runs on-device through Apple's Vision framework.

## What it does not do

- No network access, with one exception: the release build checks GitHub for updates through Sparkle, once a day, and downloads a new DMG only when you accept. Updates are EdDSA-signed and the feed is served from this repository's releases. You can turn automatic checks off in Settings, General. Nothing about your history is sent; the request carries only the app version and macOS version. Dev builds have no update feed at all.
- No sandbox: pasting into the front app requires the Accessibility permission, which the App Sandbox blocks.
- No telemetry, no crash reporting, no analytics.

## Reporting a vulnerability

Open a private security advisory on GitHub (Security tab, "Report a vulnerability") or email the maintainer listed in the repository profile. Please do not file public issues for security problems. You can expect an acknowledgement within a few days.
